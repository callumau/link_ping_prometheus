- Finding 1 — MED — readEcho skips ctx checks while datagrams keep arriving; cancellation is not bounded by one arm
  • Location: internal/prober/mtu.go:134–200 (readEcho), contradicts the claim at client.go:822–823 and mtu.go:139–145 ("the ctx check between arms is bounded…", "sweep exits within one arm (~500ms) of cancellation").
  • Trigger: readEcho only consults ctx in the arm-timeout branch (mtu.go:156–163). Every skip path — other-size datagram (167), foreign sequence (179), unrecorded ts, ts mismatch, bad HMAC — `continue`s and re-arms without checking ctx. A connected sweep socket that receives ≥1 datagram per arm (late echoes of earlier sweep sizes, or any spoofed/other traffic from the target address) never lets an arm expire, so cancellation is deferred until the absolute probe deadline — which is the applied RTO and, on an adaptive link with SRTT > 1.5s, is unbounded above (mtu.go:104–124). Effect: probeTarget's sweep join (client.go:836) can exceed stop()'s 5s bound → spurious straggler marking (stop_timeout counter + target unprobed) on a reload during an MTU sweep; the documented "one arm" bound silently doesn't hold.
  • Minimal fix: in readEcho, check cancellation once per received datagram before continuing, e.g. replace each `continue` skip with `if cerr := ctx.Err(); cerr != nil { return cerr }; continue` (or hoist a single `if ctx.Err() != nil { return ctx.Err() }` at the top of the loop after a successful Read). All callers already map the returned error to `m.mtuLost` (balanced).

- Finding 2 — MED — exit accounting races the still-live reader: a delivered echo can be counted as a timeout (fabricated loss)
  • Location: internal/prober/client.go:1295–1347 (exit defer), 1033–1040 (defer registration order), 1163–1176 (reader send-select).
  • Trigger: defers run LIFO — the accounting defer (registered last, client.go:1295) runs BEFORE `conn.Close()` (1040) and `close(done)` (1033), and `drainResponses` is non-blocking (final `default: return`, client.go:1356–1358). A reader parked in the send-select, or mid-parse of an already-read datagram, can push a response into respCh after the drain's last empty check and before/while `m.timedOut.Add(len(pending))` (1337–1347) executes; the seq is still in `pending`, so a probe that WAS echoed is counted as lost (restart path; on shutdown it is silently dropped with the series). The balance stays intact (counted exactly once) but the true-network-loss invariant is violated by ≤1 probe per loop exit, and the window stretches under `-race`/scheduler quanta. Same window applies to the panic-recovery drain (1297–1316).
  • Minimal fix: at the top of the accounting defer, `conn.Close()` (idempotent; unblocks the reader's Read with net.ErrClosed) and then bounded-join the reader before draining: `select { case <-readerDone: case <-time.After(600*time.Millisecond): }` (readerDone is closed on ANY reader exit, client.go:1043–1045). The residual one-in-flight-delivery window becomes negligible; alternatively document the accepted ≤1-probe skew at the defer.

- Finding 3 — LOW — a straggler's final per-interval snapshot can clear the Straggler flag in /status
